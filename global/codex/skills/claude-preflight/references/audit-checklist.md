# Preflight Audit Checklist — 차원별 점검 항목 · 증거 패턴 · severity 힌트

> SKILL.md Step 2/3 에서 lazy load. 각 차원에서 *무엇을 보는지*, *어디서 증거를
> 찾는지*, *어느 정도면 blocker 인지* 의 힌트다. 맹목 적용 금지 — 프로젝트 맥락에
> 맞춰 판단하고, 모든 발견은 `path:line` 증거를 단다.

---

## 1. 유지보수성

본다: 함수/파일 길이(과대 파일은 글로벌 guard 300줄 기준 참고), 책임 분리, 네이밍
일관성, 죽은 추상화, 매직 넘버/문자열, 주석과 코드의 괴리, 순환 의존.

증거 위치: 큰 파일 `wc -l`, import 그래프, 중복 네이밍, 한 함수가 여러 관심사를 섞는 곳.

blocker 힌트: 거의 없음(유지보수는 보통 should/refactor). 단 핵심 모듈이 아무도
이해 못 할 수준으로 엉켜 변경이 위험하면 should.

## 2. 중복 코드 / 불필요한 복잡성

본다: 복붙 블록, 같은 로직 3+ 곳, 쓰지 않는 추상화/제네릭/설정 옵션(YAGNI 위반),
과도한 레이어링, 발생 불가 에러핸들링, 한 번만 쓰는 헬퍼의 과설계.

증거 위치: 유사 블록 grep, 한 곳에서만 호출되는 추상화, 분기 폭증 함수.

severity: 대부분 should/refactor. 중복이 버그 동기화 실패를 부르는 곳(한쪽만 고쳐짐)
은 should↑.

## 3. 성능 병목

본다: N+1 쿼리, 루프 내 동기 I/O, 인덱스 없는 조회, 페이지네이션 없는 대량 로드,
불필요 재렌더(프론트), 캐싱 부재, 번들 크기, blocking 메인스레드, 무제한 재시도.

증거 위치: ORM 호출이 루프 안, `SELECT *` 대량, await in for-loop, 리스트 렌더에
key/memo 부재, 큰 동기 함수.

blocker 힌트: 핵심 경로가 데이터 증가에 선형 이상으로 악화돼 운영 중 장애가 예상되면
blocker. 단순 비효율은 should.

## 4. UX/UI 혼란

본다: 비일관 인터랙션, 모호한 라벨/버튼, 피드백 없는 액션, 파괴적 액션의 확인 부재,
빈 상태(empty state) 미처리, 에러를 사용자가 이해 못 하는 표현, 포커스/탭 순서,
접근성(대비·alt·aria) 기본.

증거 위치: 핸들러가 성공/실패 피드백 없이 끝나는 곳, 삭제/되돌릴 수 없는 액션,
하드코드 영문 에러를 그대로 노출, 로딩/빈/에러 3상태 중 누락.

severity: 핵심 플로우를 막히게 하는 혼란(사용자가 완료 못 함)은 should↑, 미관은 keep.

## 5. 예외 처리 / 오류 메시지 / 로딩 상태

본다: try/catch 부재 또는 과잉(삼킴), 에러 무시(빈 catch), 사용자向 메시지 품질,
로딩 인디케이터, 낙관적 업데이트 실패 롤백, 타임아웃/네트워크 실패 처리, 부분 실패.

증거 위치: 빈 `catch {}`, `catch(e){ console.log }` 후 진행, await 에 에러 경계 부재,
fetch 에 로딩/에러 상태 없음, 사용자에 스택트레이스 노출.

blocker 힌트: 핵심 경로가 실패를 삼켜 데이터 불일치/조용한 실패를 내면 blocker.
비밀/스택을 사용자에게 노출하면 보안 blocker(차원 6).

## 6. 보안

본다(우선 `/security-review` 호출, 결과 합성): 입력 검증/인젝션(SQL/XSS/command),
authn/authz 경계, 비밀·키 하드코딩, CORS/CSRF, 민감정보 로깅, 안전치 않은 역직렬화,
의존성 취약점, 권한 상승 경로, 비밀 환경변수 노출, rate limit.

증거 위치: 코드 내 `api_key=`/토큰 리터럴, 사용자 입력이 쿼리/명령에 직접, auth 체크
없는 엔드포인트, `.env` 가 커밋됨, 검증 없는 파일 업로드.

severity: 보안 불변식 위반은 **항상 blocker**(should 강등 금지). NO-GO 트리거.

## 7. 모바일 / 반응형 / 화면 크기

본다: 고정 px 폭, 브레이크포인트 부재, 작은 화면 오버플로/잘림, 터치 타깃 크기,
가로/세로, 큰 화면 빈 공간, 텍스트 줄바꿈, 모달/드롭다운의 뷰포트 처리.

증거 위치: 하드코드 width, media query 부재, `overflow` 미처리 컨테이너, 데스크탑
전용 hover 의존 인터랙션.

severity: 주 타깃이 모바일인데 작은 화면에서 핵심 기능이 깨지면 blocker. 큰 화면
미관은 keep.

## 8. 확장 시 불리한 구조

본다: 하드코딩으로 새 케이스 추가가 N곳 수정을 부르는 곳, 강결합으로 격리 변경
불가, 추상화 경계 부재, 전역 상태 남용, 새 기능이 기존을 깨기 쉬운 설계, 스키마가
확장을 막는 형태.

증거 위치: switch/if 체인이 타입마다 늘어나는 곳, 모듈 간 양방향 의존, 한 변경이
무관 모듈을 건드려야 하는 결합.

severity: 대부분 refactor. 곧 예정된 확장이 현 구조로 사실상 불가능하면 should.

## 9. 치명적 이슈 (배포 차단)

별도 검색이 아니라 1~8·10 발견 중 **배포 차단급**을 모은다. 기준: 보안 불변식
위반, 데이터 손실/오염, 핵심 경로 작동 불가/크래시, 비밀 노출, 법적·프라이버시
위반, 롤백 불가한 비가역 마이그레이션. 이 칸이 비어야 GO 에 가깝다.

## 기술부채 전용 인벤토리 (Step 3)

10번 차원을 넘어 부채를 체계적으로 모은다. 각 항목 → **pay-now / pay-later** 분류.

| 부채 종류 | 어디서 찾나 | pay-now 신호 |
|---|---|---|
| 마커 부채 | `TODO`/`FIXME`/`HACK`/`XXX` grep | 핵심 경로의 FIXME, 보안 관련 TODO |
| 데드/고아 코드 | 호출처 없는 export, 도달 불가 분기, 미사용 파일 | 혼란 유발 + 잘못 호출 위험 |
| 의존성 부채 | 매니페스트 vs lockfile, 구버전, 보안 권고 | 알려진 취약점 있는 패키지 |
| 테스트 공백 | 핵심 모듈에 테스트 부재, 커버리지 0 경로 | 배포 핵심 경로에 안전망 없음 |
| 중복 핫스팟 | 같은 로직 3+ 곳 | 버그 동기화 실패 발생 중 |
| 강결합 | 양방향 import, 전역 상태 의존 | 변경이 연쇄 파손 |
| 설정/비밀 부채 | 코드 내 환경값/비밀, 환경 분리 부재 | 비밀 노출(→ 보안 blocker) |
| 문서 부채 | 비자명 결정에 ADR/주석 부재 | 핵심 로직을 아무도 이유를 모름 |
| 우회 부채 | "임시" 패치, 주석 처리 코드, 몽키패치 | 핵심 경로의 임시방편이 고착 |
| 자동화 부채 | CI/test/lint/build 게이트 부재 | 회귀를 잡을 자동 장치 없음 |

분류 기준 한 줄: *"이걸 지금 안 갚으면 배포가 막히거나 곧 사고가 나는가?"* →
그렇다 pay-now(blocker/should), 아니다 pay-later(추적 등록, keep/refactor).

pay-later 항목도 **묻어두지 말고 리포트에 등록**한다 — 추적되지 않는 부채가 가장
위험하다. 단 등록일 뿐 배포는 막지 않는다.
