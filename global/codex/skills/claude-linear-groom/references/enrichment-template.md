# Enrichment Template — 빈약한 이슈를 빌드 가능한 spec 으로

빈약한 이슈(스크린샷-only / 빈칸 / 한 줄)를 코드·메모리 근거로 채워 **읽는 사람이
재인터뷰 없이 착수할 수 있는** 설명으로 끌어올린다. 목표는 길이가 아니라 *실행
가능성* — 어디를 건드리는지, 지금 상태가 어떤지, 무엇이 끝나야 닫히는지.

## 불변식

- **원본은 절대 삭제하지 않는다.** 스크린샷·작성자 문장은 작성자의 의도다. 보강
  텍스트는 위에 얹고, 원본은 맨 아래 `## 원본 (작성자 입력)` 아래 그대로 보존한다.
  스크린샷이 spec 인 경우(ADT-5/6/7/8 류)가 많으니 이미지 마크다운을 통째로 옮긴다.
- **근거 있는 것만 쓴다.** 파일 경로·현황은 실제 grep/Read/코드그래프로 확인한 것만.
  확인 못 한 건 추측해 단언하지 말고 "확인 필요" 로 남긴다(Karpathy 진단 원칙).
- **모르는 건 비운다.** Acceptance 가 모호하면 빈 채로 두고 `[HUMAN]` 로 표시한다.
  거짓 확신보다 정직한 공백이 낫다.

## 채울 섹션 (위→아래)

````markdown
## 배경
<왜 이 작업이 필요한가 — 한두 문장. 제목+스크린샷+코드가 말하는 문제.>

## 현황 (실측)
- `apps/web/src/.../File.tsx` (L12-30) — <현재 어떻게 동작/누락하는지, 실제로 읽은 것>
- <관련 컴포넌트/엔드포인트/테이블. 코드그래프 query_graph 나 grep 으로 확인한 것만>

## 작업 범위
- [ ] <검증 가능한 단위 작업 1>
- [ ] <단위 작업 2>
- [ ] <전환 시 제거할 옛 경로가 있으면 명시 — YAGNI>

## Acceptance
- [AUTO] <자동 검증 가능: 테스트/타입체크/특정 동작>
- [HUMAN] <사람이 봐야 하는 것: 시각검증/운영 apply 등>

---
## 원본 (작성자 입력)
<원본 description 을 한 글자도 빼지 않고 그대로. 스크린샷 마크다운 포함.>
````

## 근거 수집 순서 (이 레포 기준)

1. **코드그래프 우선** — `semantic_search_nodes` / `query_graph` 로 제목 키워드의
   실제 심볼·호출처·테스트를 찾는다. Grep 보다 싸고 구조 맥락을 준다(CLAUDE.md MCP 규칙).
2. **프로젝트 메모리** — `~/.claude/projects/<slug>/memory/MEMORY.md` 에 같은 토픽의
   `project_*` 항목이 있으면 그 함정·결정·PR 번호를 끌어온다. intake 이슈의
   `출처: project_xxx` footer 가 바로 이 연결고리다.
3. **부족하면 Grep/Read** — 그래프가 못 덮는 부분만.

## 깊이 tier

triage 스크립트가 매기는 `enrichTier` 로 작업량을 조절한다:

- **empty** (스크린샷-only/빈칸) — 항상 전체 템플릿을 채운다. 빌더가 착수 불가 상태라 우선순위.
- **shallow** (한 줄/intake 문단) — 사용자가 명시적으로 deep-pass 를 원할 때만. 이미
  `출처:` 맥락이 있으니 `## 현황`·`## Acceptance` 위주로 *증강* 하고 원본 문단은 `## 배경`
  으로 흡수한다. 멀쩡한 문단을 헛되이 갈아엎지 않는다(surgical changes).
