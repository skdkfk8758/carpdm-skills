## 이 세션에서 할 것

1. **프로젝트 지침 읽기** — 먼저 `AGENTS.md` 를 읽는다. 목표·스택·검증 3종·브랜치 규칙이
   거기 있다. 비어 있거나 placeholder 면 그 사실을 말하고 인터뷰에서 같이 채운다.
   기존 결정은 `docs/adr/` 의 `Accepted` ADR 이 SSOT 다.

2. **인터뷰** — `AskUserQuestion` 으로 묻되 **결정 갈래만** 묻는다. 코드를 읽으면 알 수
   있는 것, 이미 답이 정해진 것은 묻지 않는다. 한 번에 하나씩, 선택지마다 근거 한 줄.
   기술 선택이 갈리면 먼저 `/council-research <질문>` 으로 근거를 모은다.

3. **ADR 초안** — 결정이 잡히면 `docs/adr/NNNN-<slug>.md` 에 쓴다. 형식은
   `docs/adr/0000-template.md`, Status 는 `Proposed`. 결정이 없는 단순 작업이면
   ADR 없이 바로 스텝 계획으로 간다.

4. **스텝 계획** — ADR 의 `## Steps` 절에 **3~7 스텝**을 적는다. 스텝당 파일 3개 이하·
   커밋 1개, 스텝마다 검증 명령 1개 이상. 계획 전체를 한 화면에 제시한다.

5. **승인 후 멈춘다.** `AskUserQuestion` 으로 계획 승인을 받고 거기서 끝낸다.

## 경계

- **구현하지 않는다.** 이 세션의 산출은 ADR 문서 하나 + 승인된 스텝 계획뿐이다.
  코드 편집·테스트 실행·커밋은 다음 세션(`prompts/02-step-execution.md`)에서 한다.
- 대량 탐색·grep 이 필요하면 `scout` 에 위임한다. 직접 훑지 않는다.
- 모델 티어·스텝 규율·응답 형식은 글로벌 `~/.claude/CLAUDE.md` 가 SSOT 다.
