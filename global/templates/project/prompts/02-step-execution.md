# 스텝 실행 (기본 opus 세션)

> 사용법: 기본(opus) 세션에 아래 본문을 붙여넣는다. `<...>` 는 먼저 채운다.

---

## 대상

- ADR: `<ADR-PATH>`
- 실행할 스텝: **<STEP-NO>**

## 절차

1. ADR 을 읽고 `## Steps` 의 **해당 스텝 하나만** 실행한다. 계획에 있다고 해서
   다음 스텝을 이어 하지 않는다.
2. 한도 — 파일 **3개 이하** · 커밋 **1개**. 넘칠 것 같으면 멈추고 스텝을 쪼개자고
   보고한다(`guard-step-scope.sh` 가 4개째 파일 편집을 차단한다).
3. 검증 — ADR 의 `## Verification` 또는 `AGENTS.md` §검증 3종 명령을 **원문 그대로**
   돌린다. `|| true`·`|| echo`·`| tail` 금지. 실제 종료코드와 수치를 보고에 적는다.
4. 커밋 — 한국어 메시지, 브랜치 규칙은 `AGENTS.md` §브랜치. push·PR 은 지시받았을 때만.
5. 보고 — 글로벌 `~/.claude/rules/response-format.md` §A 5블록.
6. 끝에 `다음 스텝` 1줄 + `AskUserQuestion`. 응답 없이 다음 스텝으로 가지 않는다.

## 위임

글로벌 `~/.claude/CLAUDE.md` §모델 티어 표를 그대로 따른다. 요약:
읽기 전용 탐색·로그 조회는 `scout`, 문서·주석·테스트 추가는 `editor`, 단순 코드·설정
변경은 `fixer`, 파일 4개 이상·인터페이스/데이터 모델/의존성 변경·인증/gitops/
마이그레이션/삭제는 `implementer`. 표에 없으면 메인이 직접 한다 —
자기 작업 더블체크용 위임은 금지다.
gitops·마이그레이션·인증·삭제를 건드린 스텝은 `reviewer` 또는 `/council-review` 를 붙인다.

## 경계

- 스텝 범위 밖의 선재 버그·리팩토링은 고치지 말고 보고의 `관찰` 에 한 줄로 적는다.
- 머지·배포·브랜치 삭제는 사용자가 동작과 대상을 명시했을 때만.
