# Turn Result Board — 스킬 미경유 코드 턴의 축약 결과 보드

IMPORTANT: 스킬 파이프라인을 거치지 않고 **기본 대화 턴에서 직접 코드를 바꿨을 때**도,
종료 보고에 증거 규율을 강제한다. 스킬 턴은 craft output-contract §R 풀 보드가 이미
담당 — 본 룰은 그 **우회 현실의 안전망**(skill-first 를 대체하지 않음, 비trivial 은
여전히 스킬 경유가 정경로).

## 트리거

**코드 변경 있음 AND (2+ 파일 OR 커밋 생성 OR 테스트/빌드 실행)** 인 턴의 종료 보고.

- 스킬 경유 턴(forge/hunt/renew·linear-goal)은 **제외** — 풀 보드가 이미
  emit 됨, 이중 출력 금지.
- 질문답변·탐색·문서/설정 편집·단일 파일 오타 수정은 비대상.

## 축약 보드 (3행 필수 + 2행 조건부 — 존재하는 행만)

박스 문자(`┌─└`)·고정폭 공백 정렬 금지 — 렌더 폭 의존이라 내용이 랩핑되면
테두리가 깨진다(2026-07-29 실측, output-contract §R 동시 개정). plain markdown
리스트 + 볼드 라벨로:

```
**결과**
- **변경** — N files (+A/−D) · <브랜치>
- **커밋** — N · <hash>                    (커밋했을 때만)
- **테스트** — <러너 X/X> · <타입체크>      (돌렸을 때만)
- **검증 커맨드** — `<실행한 명령>` → <실제 출력 수치>
- **잔여** — [HUMAN] 남은 수동 확인 · 없으면 "없음" 명시
- **체크리스트** — <artifact URL> · dev <origin>   (UI 표면 + 잔여 2건+ 일 때만)
```

규칙:

1. **검증 커맨드 행이 핵심.** verification-safety V1 인스턴스 — "이 명령이 실패했다면
   지금 출력이 달랐을 것인가"에 예라고 답하는 실제 출력만. "됐음" 금지.
2. **잔여 행은 생략 불가.** 남은 게 없으면 "없음"이라고 쓴다 — 보드가 "전부 끝남"으로
   위장하는 것과 잔여 누락은 같은 실패.
3. **존재하는 행만.** 안 한 것의 행을 빈칸/추정으로 채우지 않는다.
3-1. **UI 표면을 바꿨고 잔여 `[HUMAN]` 이 2건 이상이면 체크리스트 행이 의무다** —
   `ui-verify.md` §5(아티팩트 publish)·§5.1(dev 서버를 띄운 채 인계)을 돌리고 그 URL 과
   실측 origin 을 적는다. 스킬 턴이 아니라 이 규약이 전파 경로의 끝이다 — 여기 없으면
   기본 대화 턴에서는 아무도 체크리스트를 요구하지 않는다(ADT-406 실측 누락 지점).
   잔여가 1건이면 위 `잔여` 행 한 줄로 충분하다.
3-2. **dev origin 은 포트 중복확인 뒤 실측한 값이다.** `:3000` 은 대개 이미 다른
   프로젝트·다른 브랜치가 물고 있고, 그래도 기동은 성공한다(프레임워크가 다음 빈 포트로
   옮긴다) — 그래서 충돌은 에러가 아니라 *살아 있는 남의 화면*으로 나타난다. 띄우기 전
   `devserverctl.py ports --port <포트>` 로 확인하고, 보고에는 스크립트가 **이 daemon
   소유로 찍은 포트만** 적는다(ui-verify §5.1-0.5/2).
4. **풀 보드의 정체성·평결·Acceptance·타이밍 행은 넣지 않는다** — 스킬 인프라(보안
   페이즈·AC 장부·타이밍 jsonl) 없이 채우면 거짓 green 이 된다.
5. `result:` 줄은 미포함 — 백그라운드 잡 classifier 신호용(output-contract L1)이지
   대화 턴 규격이 아니다.

## 프로그래스는 native Task 가 담당

기본 턴의 턴 내 진행 표시는 **native Task 체크리스트**(TaskCreate/TaskUpdate)가 정답 —
Workflow 잠김이 없어 라이브 갱신이 그냥 된다. 스킬 턴의 P1/P4(council 배너·ETA)는
전제 인프라가 없으므로 이식하지 않는다.

## Anti-patterns

- 축약 보드에 평결/타이밍 행을 임의 추가 — 근거 인프라 없는 거짓 green.
- 스킬 턴에서 풀 보드 + 축약 보드 이중 emit.
- 잔여 행 생략으로 "전부 끝남" 위장.
- 보드가 필요할 만큼 큰 작업을 기본 턴에서 계속 돌림 — skill-first 우회 증상, 보드는
  면죄부가 아니다.
- UI 잔여 2건+ 인데 체크리스트 행 없이 텍스트 잔여만 — 규칙 3-1 위반.
- 체크리스트를 내면서 dev 서버는 내려두거나 관례 포트를 추정해 링크 — 사람이 누르면
  ECONNREFUSED 이거나 *다른 브랜치* 화면이다(ui-verify §5.1).
- 포트 중복확인 없이 띄우고 보드에 `:3000` — 기동 성공이 그 포트를 얻었다는 증거가 아니다(3-2).
