# Response Format — 응답 형식

IMPORTANT: 모든 응답은 아래 두 형식 중 하나를 따른다. **메인 대화와 서브에이전트 보고 모두** 적용된다.

> **왜 룰 파일인가**: 실측(2026-08-04) 결과 서브에이전트는 **글로벌 `~/.claude/CLAUDE.md`
> 와 거기서 import 된 룰 본문만** 받는다. 프로젝트 `CLAUDE.md` 와 SessionStart 훅의
> `additionalContext` 는 서브에이전트에 닿지 않는다. 두 쪽 모두에 형식을 걸 수 있는
> 레이어는 이것뿐이라 훅에서 여기로 옮겼다.
>
> 한계를 분명히 한다 — 이건 **지시**지 포매터가 아니다. 출력을 기계적으로 변환하는 장치는
> 없다. 100% 결정적인 형식은 어떤 방법으로도 얻을 수 없다.

## 1. 메인 대화 — 이중 모드

이번 턴에 **파일 변경 또는 상태 변경 명령이 있었는가**로 분기한다. 애매하면 A 로 간다.

### A. 작업 응답 — Edit/Write 또는 상태 변경 Bash(git commit·push·배포·마이그레이션 등)를 수행한 턴

5블록을 이 순서로, 이 헤딩 문구 그대로.

```
## [<스코프>] <한 줄 요약>

**결론** — 무엇을 했는지 1문장.

**변경**
- <path:line> <무엇을>

**근거** — 왜 이 선택인지 1-2문장. 기존 패턴을 따랐다면 그 위치를 밝힌다.

**검증** — 실행한 명령과 실제 결과. 안 돌렸으면 '미실행'.

**남은 것** — 항목마다 `[필수]`/`[선택]` 접두 + 누가(`[HUMAN]`/모델) · 없으면 '없음'.

**다음** — 이 작업 *이후* 후보 최대 3개, 우선순위 순 · 후보 0건이면 이 블록 생략.
1. <할 일> — <왜 지금> → /<스킬>
```

- `<스코프>`: 모노레포면 `apps/web`·`apps/api`·`infra` 등 실제 경로. 단일 레포면 모듈명.
  애매하면 생략하고 `## <요약>` 만 쓴다.
- **변경** 은 `path:line` 형태 — 터미널에서 클릭 가능해야 한다.
- **검증** 에 통과하지 않은 결과를 통과한 것처럼 쓰지 않는다. 실패는 실패로, 미실행은 미실행으로.
  판정 명령에 `|| true`·`| tail` 을 붙이지 않는다 — 종료 코드가 삼켜진다.
- **남은 것** 에 미완·알려진 한계·후속 작업을 숨기지 않는다.
- **남은 것 항목은 필수 여부를 명시한다** — `[필수]` = 이걸 안 하면 이번 작업이 미완·깨짐·
  미배포(예: staged 변경 PR, 실패한 검증 재실행, 되돌려야 할 임시 상태). `[선택]` = 이번
  작업과 독립인 개선·정리·후속 아이디어. 판단 못 하면 `[필수?]` 로 두고 왜 못 정하는지
  한 줄. 접두 없는 항목은 규칙 위반 — 독자가 무엇을 지금 해야 하는지 못 가른다.

### 다음 작업 — 후보 해석 순서 (§A 전용)

**남은 것**이 *이번 작업의 잔여*라면 **다음**은 *그 이후*다. 둘은 겹치지 않는다.

- **적용 지점은 §A 작업 턴 + 코드 턴 종료 보고의 `다음` 행뿐.** §B 대화 응답·짧은 확인엔
  붙이지 않는다 — 조사 답변 끝의 로드맵은 소음이다.
- **해석 순서 — 세션 먼저, 그다음 Linear.**
  1. **이번 세션 컨텍스트**: `남은 것`의 `[선택]` 항목 · 미착수 PLAN Step · 작업 중 발견해
     보고한 후속(선재 버그·기술부채) · 이 세션에서 읽은 handoff 문서의 남은 일.
  2. **1이 0건일 때만 Linear 조회.** repo 가 Linear 에 연결돼 있을 때만 —
     활성 이슈 / `~/.claude/linear-repo-map.json` 매핑 / 브랜치명 이슈ID 중 하나가 근거.
     조회 규율은 `rules-ondemand/linear.md` §1, 정렬은 priority 내림차순 → 최근 업데이트순.
     **Linear MCP 미설치이거나 연결 근거가 없으면 `다음` 블록을 통째로 생략한다 —
     묻지 않고, 설치를 권하지 않는다.**
- **`[필수]` 잔여는 다음에서 제외.** `남은 것`의 `[필수]`는 이번 작업의 일부지 다음 작업이
  아니다. 같은 항목이 두 블록에 나오면 규칙 위반. `[선택]`은 다음 작업 후보로 승격 가능하되,
  승격했으면 `남은 것`에 중복으로 남기지 않는다.
- **최대 3개.** 더 있으면 잘라내고 마지막 줄에 `외 N건` 한 마디. 0개면 블록 생략(빈 블록·
  "없음" 금지 — `남은 것`과 달리 이건 정보가 아니라 소음이다).
- **형식** `1. <할 일> — <왜 지금> → /<스킬>`. `<왜 지금>`은 우선순위 근거 한 마디
  (차단 해소·의존 선행·이슈 priority 등). 스킬 라우팅은 아래 §스킬 라우팅 규율 그대로 —
  억지 매칭 금지, 마땅한 게 없으면 `→` 부분을 생략한다.
- **추측 금지.** 세션에도 Linear 에도 근거가 없는 항목을 지어내지 않는다. 후보를 채우려고
  일반론("테스트 커버리지 올리기")을 적는 것은 위반이다.
- 이슈가 많아 3개로 못 자르겠으면 나열하지 말고 `→ /linear-prioritize` 한 줄로 넘긴다.

### 스킬 라우팅 — 잔여 작업 제안 + 입력 기반 넛지 공통

적용 지점: A 의 **남은 것** · B 의 후속 제안 · 코드 턴 종료 보고의 **잔여** ·
훅이 주입하는 `[스킬 라우터]` 넛지 수신 시.

**풀 (넓게 대조하되 이름을 지어내지 않는다):**

1. 세션에 로드된 스킬 목록 — 글로벌 `~/.claude/skills` + 플러그인(ponytail 계열 포함)
2. 프로젝트 레벨 `.claude/skills/` · `.claude/commands/` · `.claude/workflows/`
3. **유저 전용 커맨드**(paperthin 12종: `/hate`·`/prism`·`/feynman`·`/macrothink`·
   `/debloat`·`/reorder` 등 — SSOT `rules-ondemand/paperthin-routing.md` §1).
   모델이 직접 호출할 수 없으므로 "사용자가 타이핑" 형태로만 제안한다
4. Workflow 멀티에이전트 — 사용자 옵트인 필수이므로 제안만, 실행은 요청받았을 때

**최적 규율 (paperthin-routing.md §4 와 동일 원칙):**

- 복수 매칭이면 메뉴를 나열하지 말고 **최적 1개**(+대안 최대 1개)를 골라
  "왜 이것인지" 한 줄과 함께 `→ /<이름>` 으로 붙인다.
- 억지 매칭 금지 — 그 항목을 실제로 한 단계 이상 진행시키는 것만. 없으면 안 붙인다.
- 훅 넛지(`[스킬 라우터]`)는 후보이지 명령이 아니다 — 부합 여부를 스스로 판정해
  최적 1개만 채택하고, 오탐이면 **언급 없이 무시**한다. 작업을 멈추지 않는다.
- 예: `- PR 머지 + 로컬 동기화 → /land` · `- 계획 확정 전 반박 검증 → /hate (사용자 타이핑)`

### B. 대화 응답 — 질문·조사·설명·계획 등 그 외 전부

```
[<스코프>] <한 줄 요약>

<본문 — 자유 서술>
```

헤더 1줄 + 본문. 5블록을 강요하지 않는다. 스코프가 무의미하면 헤더도 생략한다.
짧은 확인·인사·되묻기에는 어느 형식도 강요하지 않는다.

## 2. 서브에이전트 보고 — 공통 형식

호출하는 쪽이 프롬프트에 과제별 항목을 더한다. 아래는 **과제와 무관하게 항상** 지킨다.

- **결론 먼저.** 무엇을 했고 결과가 무엇인지 첫 문단에. 과정 서술을 앞에 놓지 않는다.
- **근거는 `경로:줄`.** "확인했다" 로 끝내지 말고 어디서 확인했는지 적는다.
- **`## 확인 못 한 것` 절 필수.** 없으면 "없음" 이라고 쓴다. 모르는 것을 아는 것처럼
  적는 쪽이 조사 자체보다 비싸다.
- **파일 내용을 통째로 붙여넣지 않는다.** 경로 + 핵심 라인만 인용한다.
- **명령 출력이 20줄을 넘으면 요약만.** 전문을 보고서에 옮기지 않는다.
- 호출한 쪽이 지정한 줄 수 제한을 지킨다.

## 3. 적용 범위

응답 텍스트에만 적용된다. **커밋 메시지·코드 주석·문서·PR 본문에는 적용하지 않는다** —
그쪽은 각자의 규약(글로벌 `CLAUDE.md` §Language, 프로젝트 지침)을 따른다.
