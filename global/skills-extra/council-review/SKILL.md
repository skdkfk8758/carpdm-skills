# Council Review — 세 렌즈 병렬 리뷰

한 명의 리뷰어는 자기가 보는 축만 본다. 이 스킬은 **서로 다른 렌즈 셋을 동시에** 걸고,
겹치는 지적(합의)과 한 렌즈만 본 지적(불일치)을 갈라 메인이 판정한다.
**편집·커밋·머지를 하지 않는다.**

## Step 1 — 대상 확정

인자에 따라 리뷰 대상 diff 명령을 하나로 못 박는다.

| 인자 | 대상 명령 |
|---|---|
| 없음 | `git diff $(git merge-base HEAD origin/<trunk>)...HEAD` — trunk 는 repo 관례(`develop` 또는 `main`) |
| 브랜치명 | `git diff $(git merge-base <branch> HEAD)...<branch>` |
| PR 번호·URL | `gh pr diff <n>` 또는 `glab mr diff <n>` — 호스트에 맞춰 |
| 커밋 범위 | 받은 범위 그대로 (`A...B`) |

그다음 **배경 한 문단**을 만든다 — 이 변경이 풀려는 문제, 관련 이슈 ID, 사용자가 말한
요청 요약. 페르소나는 이 문단 말고는 맥락이 없다.

대상이 비었으면(diff 0줄) 여기서 멈추고 그 사실을 보고한다.

## Step 2 — 세 렌즈 동시 spawn

`Agent` 호출 **세 개를 한 메시지 안에서** 낸다. 순차로 띄우지 않는다.

```
Agent(subagent_type: persona-karpathy, prompt: <대상 diff 명령> + <배경 문단> + "보고 형식은 에이전트 정의대로")
Agent(subagent_type: persona-torvalds, prompt: 같은 내용)
Agent(subagent_type: persona-pocock,   prompt: 같은 내용)
```

- `name` 을 주지 않는다. 이름을 붙이면 재사용 대상이 되고 병렬 spawn 이 꼬인다.
- 프롬프트는 **세 개가 동일**해야 한다. 렌즈별로 힌트를 다르게 주면 합의/불일치 판정이
  무의미해진다. 렌즈 차이는 에이전트 정의가 이미 갖고 있다.
- 선택 인자 `--with hightower,abramov` 가 있으면 해당 페르소나를 같은 메시지에 추가한다
  (`persona-hightower`·`persona-abramov`). 운영 변경·gitops·공개 API 변경이면 권한다.

## Step 3 — 메인이 병합

세 보고를 받은 뒤 메인이 직접 판정한다. 보고를 그대로 이어 붙이지 않는다.

1. **합의** — 2인 이상이 같은 지점을 지적한 것. `파일:줄` + 어느 렌즈들이 봤는지.
2. **불일치** — 한 렌즈만 지적한 것. **렌즈 이름을 표기**한다. 다른 렌즈가 "일부러
   무시하는" 축이라 안 본 것인지, 실제로 이견인지 구분해서 적는다.
3. **판정** — `머지 가능` 또는 `수정 필요` + 근거. 페르소나의 결론을 다수결로 세지
   않는다 — 메인이 diff 를 보고 판단하고, 근거는 `파일:줄` 로 댄다.
4. **가르는 질문 1개** — 불일치를 푸는 데 필요한 사용자 결정 하나를
   `AskUserQuestion` 으로 묻는다. 불일치가 없으면 이 절을 생략한다.
5. `## 확인 못 한 것` — 필수. 페르소나가 못 본 것 + 메인이 확인 못 한 것.

## Step 4 — 경계

- 편집·커밋·머지·push 를 하지 않는다. 이 스킬의 산출은 **판정 보고 하나**다.
- 사용자가 "고쳐줘" 라고 지시하면 그때 별도 스텝으로 구현에 들어간다. 리뷰 결과를
  받자마자 이어서 고치지 않는다.
- 페르소나 보고를 원문 그대로 옮기지 않는다. 병합된 표 하나가 산출이다.
