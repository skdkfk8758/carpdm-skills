# Response Format — 마무리 판정 (온디맨드)

`~/.claude/rules/response-format.md` §A 작업 턴의 `남은 것`·`정리` 를 쓰기 전에 Read 한다 — 세션당 1회, 상시 로드 아님.
2026-09-11 상시 컨텍스트 절감으로 response-format.md 에서 떼어냈다. 2026-09-13 `다음`(다음 작업 체이닝)·스킬 라우팅
절을 폐지하고 §정리 판정을 넣었다 — 응답 끝 후속 제안이 실사용에서 불편하다는 사용자 판단.

## 세션 경계 — 한 세션 = 한 작업 (§A 전용)

목적: **한 세션에서 불필요하게 많은 작업이 일어나지 않게 한다.** 컨텍스트가 길어질수록
검증 품질은 떨어지고 되돌림 비용은 오른다.

- **작업 단위** = 사용자가 이번 세션에서 요청한 것 + 그것을 닫는 데 필요한 `[필수]`.
  그 밖의 모든 것은 이번 세션 밖이다.
- **다음 작업을 제안·체이닝하지 않는다.** 응답에 후속 후보·스킬 추천·"이어서 할까요?" 를 붙이지 않는다.
  사용자가 다음 작업을 직접 지시하면 그대로 따른다 — 새 세션 권장 문구로 되묻지 않는다.
- **작업 중 발견한 것은 고치지 않고 `관찰` 에 사실로만 적는다.** 선재 버그·기술부채·주변 리팩토링 여지가 여기다.
  요청된 동작이 그것 없이는 성립하지 않을 때만 예외.
- **범위가 넓어지는 신호가 보이면 멈춘다** — 대상 파일이 처음 계획의 2배를 넘거나, 두 번째
  독립 주제로 넘어가려 하거나, 검증이 실패해 원인이 다른 모듈로 옮겨갈 때. 그 시점에서 §A 로
  턴을 닫고 이번 작업을 닫는 데 남은 것만 `[필수]` 로 적는다.

## 남은 것 게이트 — `[필수]` 는 사람만 풀 수 있는 블로커만 남긴다 (§A 전용)

목적: 결정·승인·실행이 필요한 항목이 `[필수]` 로 다음 턴에 밀리는 것을 막는다. 실측(2026-09-10,
DB-Manager 세션)에서 `[필수]` 8건 중 사람만 풀 수 있는 블로커는 0건이었다 — 전부 인터뷰·실행·
재분류로 없앨 수 있는 항목이었다.

§A 를 내기 **전에** 남은 것 후보를 하나씩 아래 넷 중 하나로 판정한다. 판정 없이 적는 `[필수]` 는 위반이다.

| 유형 | 판정 기준 | 처리 |
|---|---|---|
| ① 지금 할 수 있다 | 결정 불필요 · 가역 · 이번 작업 범위 안 (권한 600, 산출물 커밋, 문서 갱신, PR 생성 — 글로벌 `CLAUDE.md` §Independent skill execution 이 PR 생성까지 허용) | **한다.** 남은 것에 적지 않는다 |
| ② 사용자 결정·승인이 필요하다 | 머지 · 배포 · 운영 DB 적용 · 삭제 · 브랜치명 · 팀 선택 | 턴을 닫지 않고 **AskUserQuestion 으로 지금 묻는다**(최대 4문항 묶음). 답을 받아 처리한 뒤 §A 를 낸다. 사용자가 "나중에" 라고 한 항목만 `[필수][HUMAN]` 로 남긴다 |
| ③ 사람·외부만 할 수 있다 | 내게 없는 자격증명 · 외부 담당자 회신 · 다른 세션의 브랜치 · 물리 작업 | `[필수][HUMAN]` + **왜 내가 못 하는지 한 줄**(시도한 경로와 실제 에러 — 글로벌 `CLAUDE.md` §진단의 "불가능은 최후 판정" 기준). 유일하게 남아도 되는 `[필수]` |
| ④ 이번 작업을 닫는 데 필요 없다 | 선재 버그 · 기술부채 · 인접 트랙 문제 · 개선 아이디어 · 후속 작업 | 남은 것에 적지 않는다. 사실로 남길 가치가 있으면 `관찰` 에 한 줄 |

자가 점검: §A 의 `[필수]` 마다 "`[HUMAN]` 이 붙어 있고 내가 못 하는 이유가 적혀 있는가?" 하나라도
아니면 턴을 닫지 말고 ①이면 실행, ②면 인터뷰로 돌아간다.

- ②의 인터뷰는 범위 확장이 아니다 — 이번 작업을 **닫기 위한** 결정만 묻는다. 새 주제는 ④다.
- ②를 물을 상대가 없는 실행(백그라운드·자동 루프·서브에이전트)에서는 질문 문장을 그대로 적어
  `[필수][HUMAN]` 으로 남긴다.
- ①로 판정해 실행한 것은 `변경`·`검증` 블록에 들어간다 — 남은 것에서 "했다" 로 적지 않는다.

## 정리 판정 — worktree 를 지워도 되는가 (§A 전용)

`남은 것` 이 '없음' 일 때 턴 마지막 `정리` 블록에 쓴다. **판정해 알리기만 하고 지우지 않는다** — 삭제는
사용자가 대상을 지정해 요청할 때만 한다. `[필수]` 가 남았으면 판정하지 않고 `보류 — 필수 N건` 만 쓴다.

대상 = **이번 세션이 만들었거나 커밋한** worktree·브랜치. 다른 세션이 만든 것은 대상이 아니다(보이면 `관찰` 에 한 줄).

worktree 마다 아래를 **명령으로** 확인하고, 전부 충족할 때만 "삭제해도 됨" 이다. 하나라도 아니면 "보존" + 걸린 조건.

| 조건 | 확인 명령 |
|---|---|
| 작업 트리 clean | `git -C <wt> status --porcelain` 출력 없음 |
| 커밋이 trunk 에 반영됨 | MR/PR `state == merged` 재조회, 또는 `git cherry origin/<trunk> <branch>` 가 전부 `-`. squash 머지면 MR 상태로 판정 |
| 원격 브랜치 정리됨 또는 머지 뒤 불필요 | `git ls-remote --heads origin <branch>` |
| 붙어 있는 다른 세션·프로세스 없음 | 그 경로를 cwd 로 쓰는 프로세스(`lsof +D <wt>` 등)·떠 있는 compose 스택 없음 |

형식:

```
**정리** — 필수 0건. 삭제해도 됩니다: `<wt 경로>`(<브랜치>, !NN 머지) · 보존: `<wt 경로>` — <걸린 조건>.
```

- worktree 를 쓰지 않은 세션은 `정리할 worktree 없음` 한 줄.
- scratchpad·임시 port-forward 처럼 세션이 연 임시 자원은 턴 안에서 직접 닫고 `검증` 에 적는다 — 정리 블록 대상이 아니다.
