# 짧은 호흡 — 스텝 단위 작업 규율

## 왜
사용자는 한 번에 3개 파일 정도까지 실제로 읽고 판단한다. 그 이상을 한 호흡에 바꾸면
승인은 형식이 되고, 되돌림 비용은 마지막 승인 이후 바뀐 파일 수에 비례해 커진다.
스텝을 짧게 끊으면 매 스텝이 검토 가능하고 되돌릴 수 있다.

## 스텝의 정의
- 파일 **3개 이하** (`~/.claude`·스크래치패드·서브에이전트 작업은 세지 않는다)
- 커밋 **1개** — 스텝이 곧 커밋 단위다
- 검증 명령 **1개 이상** — 원문과 실제 종료코드를 보고에 적는다

## 절차
1. 착수 전 **3~7개 스텝 계획**을 한 화면에 제시한다 (스텝마다: 목표 · 파일 · 검증 명령).
2. `AskUserQuestion` 으로 계획 승인을 받는다.
3. **스텝 1만** 실행한다. 계획에 있다고 해서 2를 이어 하지 않는다.
4. 스텝 끝: `rules/response-format.md` §A 보고 + `다음 스텝` 1줄 + `AskUserQuestion`.
5. 응답을 받으면 다음 스텝으로 간다. 응답 없이 진행하지 않는다.

## 리셋 규칙
파일 카운터는 **사용자 입력**(UserPromptSubmit)과 **AskUserQuestion 응답**에 리셋된다.
둘 다 "다음 스텝 승인"이기 때문이다. 그 외에는 리셋되지 않는다 —
스스로 턴을 끊거나 다른 도구를 끼워 넣는다고 예산이 돌아오지 않는다.

## 면제
- `~/.claude/**` — 하네스 설정이지 작업 산출물이 아니다
- `$TMPDIR/**` · `/private/tmp/claude-*` — 스크래치패드
- 서브에이전트(`transcript_path` 에 `/subagents/`, 또는 `agent_id` 존재) — 자체 예산으로 돈다
- 이미 이번 스텝에 기록된 파일 재편집

## 변수
- 끄기: `GUARD_STEP_DISABLE=1` (`guard-step-scope.sh`·`guard-step-plan-nudge.sh` 공통)
- 한도: `GUARD_STEP_MAX_FILES` (기본 3)

## ADR 연계
설계 결정이 나오면 **스텝 0** 으로 `docs/adr/NNNN-*.md` 에 먼저 기록하고,
그 ADR 을 스텝 계획의 목표로 삼는다. 결정이 문서로 고정돼야 스텝이 흔들리지 않는다.
