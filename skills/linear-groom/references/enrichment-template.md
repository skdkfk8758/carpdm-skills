# Enrichment Template — 빈약한 이슈를 빌드 가능한 spec 으로

빈약한 이슈(스크린샷-only / 빈칸 / 한 줄)를 코드·메모리 근거로 채워 **읽는 사람이
재인터뷰 없이 착수할 수 있는** 설명으로 끌어올린다. 목표는 길이가 아니라 *실행
가능성* — 어디를 건드리는지, 지금 상태가 어떤지, 무엇이 끝나야 닫히는지.

## 불변식

- **원본은 절대 잃지 않는다 — 단 코멘트로 옮긴다.** 스크린샷·작성자 문장은 작성자의
  의도다. 본문을 새로 쓰기 **전에** 원본 전문을 `save_comment` 로 이슈 **코멘트**에
  옮기고(이미지 마크다운 통째로), 그다음 본문을 교체한다. 순서를 뒤집으면 코멘트가
  실패했을 때 원본이 사라진다. 코멘트는 본문 600자 계약 밖이라 스크린샷을 담을 수 있다.
  이미 이관한 이슈는 재이관하지 않는다.
- **본문은 register 계약을 따른다.** 헤딩 화이트리스트(`## 작업 내용`/`## 수용 기준`/
  `## 추천` 항상, `## 범위 밖`/`## 다음 작업` 조건부), 작업 내용 ≤3줄, 수용 기준 ≤5개,
  본문 ≤600자(`>` 인용줄·코드블록 제외), 산문에 파일경로·심볼명 금지. SSOT 는
  `~/.claude/skills/linear-register/SKILL.md` 의 본문 템플릿 절 — 여기 복제하지 않는다.
- **근거 있는 것만 쓴다.** 현황은 실제 grep/Read/코드그래프로 확인한 것만. 확인 못 한
  건 추측해 단언하지 말고 "확인 필요" 로 남긴다(Karpathy 진단 원칙). **단 근거로 쓴
  파일 경로를 본문에 옮겨 적지는 않는다** — 근거 수집은 *무엇을 쓸지* 정하기 위한 것이지
  경로 목록을 이슈에 남기기 위한 게 아니다.
- **모르는 건 비운다.** Acceptance 가 모호하면 빈 채로 두고 `[HUMAN]` 로 표시한다.
  거짓 확신보다 정직한 공백이 낫다.

## 채울 섹션 (위→아래)

````markdown
## 작업 내용
<무엇을 하는지 — 쉬운 말 3줄 이내. 왜 필요한지는 첫 구절에 한 번만 녹인다.>

## 수용 기준
- [ ] [AUTO] <자동 검증 가능: 테스트/타입체크/특정 동작>
- [ ] [HUMAN] <사람이 봐야 하는 것: 시각검증/운영 apply 등>

## 범위 밖   ← 이 이슈가 안 하는 것이 있을 때
- <경계>

## 추천
<`~/.claude/skills/linear-register/references/recommend-section.md` §A 규칙 그대로 —
권장 스킬 1줄 + 시작 프롬프트 코드블록 1개.>

## 다음 작업   ← 이슈가 다른 이슈와 관계(blocks/blockedBy/parent)로 연결됐을 때만
<§B 규칙 — 다음 이슈 전방 포인터 + kickoff 프롬프트. 단건이면 생략.>

> AI 가 보강
````

원본은 위 본문 **밖**, 이슈 코멘트에 산다(불변식 1). 본문에 `## 원본` 섹션을 만들지 않는다.

## 근거 수집 순서 (이 레포 기준)

1. **코드그래프 우선** — `semantic_search_nodes` / `query_graph` 로 제목 키워드의
   실제 심볼·호출처·테스트를 찾는다. Grep 보다 싸고 구조 맥락을 준다(CLAUDE.md MCP 규칙).
2. **프로젝트 메모리** — `~/.claude/projects/<slug>/memory/MEMORY.md` 에 같은 토픽의
   `project_*` 항목이 있으면 그 함정·결정·PR 번호를 끌어온다. intake 이슈의
   `출처: project_xxx` footer 가 바로 이 연결고리다.
3. **부족하면 Grep/Read** — 그래프가 못 덮는 부분만.

## 깊이 tier

triage 스크립트가 매기는 `enrichTier` 로 작업량을 조절한다:

- **empty** (스크린샷-only/빈칸) — 항상 전체 템플릿을 채운다. 빌더가 착수 불가 상태라 우선순위.
- **shallow** (한 줄/intake 문단) — 사용자가 명시적으로 deep-pass 를 원할 때만. 이미
  `> 출처:` 맥락이 있으니 `## 수용 기준`·`## 추천` 위주로 *증강* 하고 원본 문단은
  `## 작업 내용` 으로 흡수한다(별도 섹션을 만들지 않는다). 멀쩡한 문단을 헛되이
  갈아엎지 않는다(surgical changes). `> 출처:` 줄은 그대로 둔다 — 인용줄 carve-out.
