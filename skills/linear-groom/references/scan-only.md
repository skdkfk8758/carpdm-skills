# Scan-only 모드 — 무인 주기 실행용 갭 리포트

승인할 사람이 없는 실행(주기 automation·백그라운드 잡)에서 백로그 갭을 **발견해 리포트만**
한다. 백로그를 바꾸지 않는다 — 반영은 사람이 세션에서 `/linear-groom` 을 돌려 승인한 뒤에만.

## 왜 반영을 안 하나

기본 모드의 핵심 불변식은 "모든 write 는 승인 게이트 뒤"(SKILL.md)이고, 배치 적합성 판정은
스크립트가 아니라 모델 판단이다(Step 3a-2). 무인 실행에서 그 판단을 자동 반영하면 가드가
사라진다 — 매 회 흔들리는 재배치·본문 덮어쓰기가 사람 눈 없이 누적된다. 그래서 무인 실행의
산출물은 **표 한 장**이지 write 가 아니다. 자동화의 가치는 반영이 아니라 "고아 7건·빈약
3건이 생겼다"를 주기적으로 알려주는 데 있다.

## 진입

호출 프롬프트에 `scan-only` 가 명시됐을 때만. 사람이 대화로 부른 경우는 기본(interactive)
모드다 — 무인처럼 보인다는 이유로 스스로 이 모드로 내려가지 않는다.

리포트 대상 이슈는 프롬프트가 `report: <ISSUE-ID>` 로 지정한다.

**리포트 이슈 자신은 스캔 대상에서 제외한다** — open 상태로 영구히 남는 운영용 이슈라,
빼지 않으면 매주 자기 자신을 "고아 이슈"로 리포트한다.

## 허용/금지 write

- **허용 — 지정 리포트 이슈에 코멘트 1건**(`save_comment`). 이슈 필드가 아니라 append 라
  되돌리기 쉽고, 잘못돼도 백로그 상태를 오염시키지 않는다.
- **금지 — `save_issue` / `save_project` 전부.** 그룹핑·재배치·보강·중복 마킹·프로젝트
  위생 어느 것도 반영하지 않는다. 리포트 이슈 자체도 생성하지 않는다(아래 참조).

## 워크플로

1. **Step 0~3 은 기본 모드와 동일** — MCP 감지, 전수 조회, 결정론 분류, 매핑/재배치 검토/
   보강안/중복/프로젝트 위생 판정까지 그대로 한다. 리포트의 값은 이 분석의 질에서 나온다.
2. **Step 4 의 표를 만든다** — 블록 구성도 동일(그룹핑·재배치·새 프로젝트 제안·중복·프로젝트
   위생·보강). 단 **승인 요청 문구는 붙이지 않는다** — 답할 사람이 없다.
3. **코멘트 게시** — 아래 포맷으로 리포트 이슈에 코멘트 1건.
4. **Step 5·6 은 실행하지 않는다.** 반영이 없으니 반영 검증도 없다.

### 보강 블록은 요지만

보강 대상의 **전체 마크다운 본문은 코멘트에 넣지 않는다** — 이슈 하나당 수십 줄이라 코멘트가
읽을 수 없게 부푼다. 기본 모드 Step 4 와 같은 한 줄 요지(배경/현황/작업 내용/수용 기준/추천)만.
전문은 사람이 승인 세션에서 다시 생성한다.

## 코멘트 포맷

```markdown
## 백로그 갭 스캔 — YYYY-MM-DD (scan-only)

스코프: <팀> · open 이슈 N건 · 프로젝트 M개

**요약**: 고아 A건 · 재배치 후보 B건 · 빈약 C건 · 중복 후보 D건 · 프로젝트 위생 E건

<Step 4 의 표 블록들 — 있는 것만>

---
반영 안 됨(scan-only). 승인·반영은 세션에서 `/linear-groom` 실행.
```

- 실측 수치만 쓴다. 스캔이 잘렸으면(페이지네이션 미완 등) 그 사실을 요약 줄에 명시한다 —
  잘린 스캔을 전수인 척 보고하면 사용자는 커버됐다고 믿는다.

## no-op 규칙

**갭이 0건이면 코멘트를 남기지 않는다.** 매주 "할 일 없음" 코멘트가 쌓이면 알림 피로로
리포트 자체가 무시된다. 실행 여부는 실행 이력(`orca automations runs` 등)으로 확인한다.

세션 출력에는 "갭 0건 — 코멘트 생략" 을 남긴다.

## 리포트 이슈를 못 찾을 때

`report:` 로 받은 ID 가 조회되지 않거나 지정 자체가 없으면:

1. 팀에서 제목으로 후보를 찾아본다(예: "백로그 위생").
2. 그래도 없으면 **이슈를 만들지 않는다** — 무인 실행이 새 이슈를 만드는 건 사용자가
   승인한 적 없는 write 다. 세션 출력에 표를 그대로 남기고 "리포트 대상 미지정/미발견"
   을 보고한 뒤 끝낸다.

## MCP 미인증

Step 0 에서 Linear MCP 가 없거나 인증이 만료됐으면 조용히 끝내지 말고 **그 사실을 세션
출력에 명시**하고 종료한다. 무인 실행에서 조용한 실패는 "갭 0건"과 구분되지 않아, 스캔이
몇 주째 안 돌고 있다는 걸 아무도 모르게 된다.

## Anti-patterns

- scan-only 인데 `save_issue`/`save_project` 호출 — 승인자 없는 반영.
- 리포트 이슈가 없다고 새로 생성 — 미승인 write.
- 갭 0건에 "이상 없음" 코멘트 게시 — 알림 피로, 리포트 무시로 이어짐.
- 보강 전문을 코멘트에 통째 붙임 — 읽히지 않는 코멘트.
- 잘린 스캔을 전수처럼 보고 — 누락이 조용히 커버된 것처럼 보임.
- MCP 미인증을 조용히 통과 — 몇 주 무동작을 아무도 모름.
