# Result format — deep-* 공통 산출물 제시 규격 (SSOT)

> 이 파일이 `deep-interview` 와 `deep-plan` 의 **종료 시 result 블록** 단일 소스다.
> 두 스킬 모두 이 포맷을 읽어 emit 한다 — 복제하지 말 것(drift 차단). 한쪽만
> 바꾸지 말고 이 파일을 바꿔라.

스킬이 산출물을 다 만들고 멈추는 지점에서, 정확히 아래 모양으로 보고한다. 목적은
두 가지: (1) 무엇을 산출했는지 한 줄로 못 박고, (2) 각 산출물을 **바로 열 수 있는
명령**을 함께 줘서 사용자가 경로를 손으로 옮길 필요가 없게 한다.

## 블록 모양 (고정)

```
result: <한 줄 — 무엇을 산출했는지. 핵심 수치 포함(ambiguity %, 컴포넌트 수 등)>

산출물 — 열기:
- <라벨> `<상대경로>`  →  `open <상대경로>`
- <라벨> `<상대경로>`  →  `open <상대경로>`

(`open` = macOS. Linux `xdg-open <path>`, Windows `start <path>`.
 경로는 터미널에서 클릭으로도 열린다.)
```

## 규칙

- **`result:` 줄을 그대로 쓴다** — 글자 그대로 `result:` 로 시작. 백그라운드
  잡에서 이 줄이 완료 신호로도 쓰인다. 한 줄, self-contained(요청을 못 본 사람도
  읽힘).
- **존재하는 산출물만 행으로** 낸다. 만들지 않은 산출물 행을 넣지 말 것(예:
  UI 가 아니라 HTML 시안을 안 만들었으면 시안 행 생략).
- **경로는 프로젝트 루트 기준 상대경로.** 절대경로 금지(사용자 환경마다 다름).
- **라벨은 한국어 한 단어급** — `PLAN` / `시안` / `SPEC` 처럼 즉시 식별되게.
- 끝의 cross-platform 주석은 **한 번만**, 블록 맨 아래에. 매 행에 반복 금지.

## 스킬별 산출물 매핑

| 스킬 | 행으로 낼 산출물 |
|---|---|
| `deep-plan` | `PLAN` (`docs/plans/…md`) + (UI plan 이면) `시안` (`…html`) |
| `deep-interview` | `SPEC` (`docs/specs/…md` 또는 프로젝트 spec 위치) |

deep-interview 는 이 블록을 spec 결정화 직후 내고, **그다음에** 다음 스킬 라우팅
추천(Phase 5)을 잇는다 — result 블록이 라우팅을 대체하지 않는다.
